# 火山引擎语音能力接入说明（v0.1.86+）

App 支持火山引擎的两项语音能力，入口都在「语音配置」页：

| 能力 | 状态 | 说明 |
|---|---|---|
| 声音复刻（音色克隆） | ✅ 可用（需开通+部署代理） | 上传音频克隆你的音色，AI 用该音色朗读；AI 大脑仍是你选的 Kimi 等文本模型。桌面端可文件导入，Web/手机同理。 |
| 端到端实时语音 | ⚠️ 骨架，未启用联调 | 语音直接进、豆包语音直接出，低延迟可打断；大脑换成豆包。桌面端需原生桥接，Web/手机需另部署中继。 |

## 一、声音复刻（推荐，立即可用）

### 前置条件
1. 火山引擎控制台开通「豆包语音 → 声音复刻 2.0」服务（新用户有免费额度）。
2. 拿到 **APP ID** 和 **Access Token**。
3. 有一个可公网访问的 TTS 代理（见 `tts-proxy/app.py`，已内置火山分支）。

### 配置步骤
1. 部署 `tts-proxy/app.py` 到云函数（阿里云 FC 或任意 Python HTTP 环境），设置环境变量：
   - `VOLC_APP_ID` = 你的 APP ID
   - `VOLC_ACCESS_TOKEN` = 你的 Access Token
   - 可选 `VOLC_CLONE_ENDPOINT` / `VOLC_TTS_ENDPOINT` / `VOLC_TTS_CLUSTER`（默认见 `tts-proxy/README.md`）
2. App →「语音配置」→「第三方语音服务配置」：服务商选「火山引擎 / 豆包声音复刻」，端点填云函数地址，保存。
3. （可选）「语音配置 → 火山引擎」区填写同一组 APP ID / Access Token 并保存（供实时语音预留；声音复刻的密钥实际在云函数，不必填这里也能用）。
4. 回到「声音克隆」：导入一段 10~20 秒清晰人声（或桌面端录音），点「克隆为 AI 发音」。
5. 成功后 AI 回复即用克隆音色朗读。

> 火山声音复刻有多个产品形态（豆包语音 HTTP API / RTC TrainTTSVoiceType），端点与请求体不同。代理里的 `_volc_create_voice` / `_volc_synthesize` 采用通用结构并把端点做成环境变量可覆盖。**未做真实 API 联调（无密钥环境），开通后请按火山控制台给出的端点/返回校准 payload。**

## 二、端到端实时语音（骨架，待联调）

### 为什么需要原生桥接
- 浏览器与 Tauri WebView 的 WebSocket **不能自定义鉴权 header**，而火山连接要求 `X-Api-App-ID` / `X-Api-Access-Key` 等 header。
- macOS 的 Tauri WKWebView **不提供 getUserMedia**，拿不到实时麦克风 PCM。
- 因此桌面端必须由 Rust 建 WebSocket + 用 cpal 采集麦克风；Web/手机端需要额外的 WS 中继服务。

### 已交付的骨架
- `desktop/src-tauri/src/volc_realtime.rs`：二进制协议编解码（有 5 个单元测试全部通过）、Tauri 命令 start/send/stop、会话状态机。含 TODO 标注 cpal 采集位置。
- `src/core/volcRealtime.ts`：前端封装，`isVolcRealtimeSupported()` 当前返回 false（避免暴露不可用功能）。
- `src/core/volcConfig.ts`：共用凭据配置（Token 混淆存储，不进云同步）。

### 启用步骤（需联网下载 Rust 依赖 + 密钥联调）
1. 在 `desktop/src-tauri/Cargo.toml` 恢复注释掉的依赖：`cpal`、`tokio`、`tokio-tungstenite`、`futures-util`、`base64`、`uuid`。
2. 在 `lib.rs` 恢复 `mod volc_realtime;`、`use tauri::Manager;`、`.manage(volc_realtime::VolcState::new())` 及三个命令的注册。
3. 把 `volc_realtime.rs` 里 `start_volc_realtime` 的 TODO 处接入 cpal 采集（16kHz 单声道，回调里送 `audio_tx`）。
4. 按你开通的具体产品形态（老版 v3 二进制 / 新版 3.0 JSON）校准 `start_session_payload` 与下行事件解析。
5. 把 `volcRealtime.ts` 的 `isVolcRealtimeSupported()` 改为 `return isDesktopApp()`。
6. `cargo check` → 打包 → 真机联调。
7. Web/手机端若要支持，需另部署可设置自定义 header 的 WebSocket 中继服务。

### 当前限制
- 无火山密钥，无法真机联调；协议细节（事件号、字段、cluster、音色名）需按实际开通信息校准。
- 构建环境无法从 crates.io 下载新依赖，故 Rust 桥接未接入编译（已回退，保证现有桌面构建正常）。
